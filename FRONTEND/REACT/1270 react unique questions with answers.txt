1. Can hooks be used inside loops or conditions?
Category: Hooks Rules
Hooks in React must always be called at the top level of a component or a custom hook to maintain consistent behavior. Using hooks inside loops or conditional statements breaks the predictable order of hook calls, which React relies on internally to manage state and effects. This can lead to bugs and unexpected behaviors because React cannot guarantee which hooks are called or in what order. By enforcing this rule, React ensures the hook state and effects are stable and consistent across renders, making your components predictable and maintainable.
2. Can React components return multiple elements?
Category: Basics
React components can indeed return multiple elements, but these elements must be wrapped in a single parent element or a React fragment. This approach allows React to properly manage and reconcile the DOM tree efficiently. Fragments are especially useful because they let you group elements without introducing additional nodes in the DOM, which keeps the structure clean and performance optimized. Returning multiple elements fosters component flexibility and composability, allowing developers to build complex interfaces out of simple, reusable pieces.
3. Can you set state directly?
Category: State
Directly modifying state variables is discouraged in React because it circumvents React’s state management system, leading to inconsistencies and unpredictable UI updates. State updates should always be performed through designated setter functions or dispatchers that React provides. These functions ensure that changes trigger re-renders when necessary and that updates are batched for optimal performance. Maintaining this discipline allows React to synchronize the state with the UI seamlessly and avoids subtle bugs caused by direct mutations.
4. Can you use if statements inside JSX?
Category: JSX
JSX does not support traditional if statements inside its syntax because JSX is an expression language, not a statement-based one. Instead, conditional rendering is achieved using JavaScript expressions like ternary operators or logical AND operators inside JSX. This preserves the declarative nature of JSX and keeps the markup concise and readable. For complex conditions, it’s common practice to perform conditional logic outside the JSX and then use the results inside it, keeping the UI code clean and straightforward.
5. Can you use multiple useEffect hooks in a component?
Category: Hooks
Yes, React allows multiple useEffect hooks in the same component. This design enables developers to separate different side effects into isolated hooks, each handling a specific concern such as fetching data, subscriptions, or DOM updates. This modularization improves code clarity, reusability, and maintainability by avoiding complex monolithic effects. Each useEffect runs independently and in the order they appear, helping to organize side effects efficiently.
6. How can useRef be used to access DOM elements?
Category: Hooks
The useRef hook provides a way to create a persistent reference to a DOM element, enabling direct manipulation or access to its properties. By attaching the ref to an element, React updates the ref’s current property with the DOM node once it is rendered. This reference enables imperative operations like focusing inputs, measuring size, or interacting with third-party libraries that require direct DOM access, all without causing re-renders, preserving React’s declarative nature.
7. How can useRef help avoid re-renders?
Category: Hooks
Unlike state variables, updating a useRef’s current property does not trigger a re-render. This makes useRef ideal for storing mutable values that persist across renders but do not directly affect the rendered output. For example, timers, previous values, or any non-visual data can be stored in refs to avoid unnecessary component updates and optimize performance by reducing render cycles.

13. How can you memoize a component with React.memo?
Category: Performance
React.memo is a higher-order component that optimizes functional components by memoizing their rendered output. When a component wrapped with React.memo receives the same props on subsequent renders, React reuses the previous render result instead of recalculating the component tree. This prevents unnecessary rendering and improves performance, especially for components that render complex UI or are used frequently. Memoization is particularly effective when combined with immutable props and pure functions, ensuring that renders are only triggered when relevant data changes.

20. How do HOCs differ from render props?
Category: Advanced Patterns
Higher-Order Components (HOCs) and render props are both patterns to share logic between components. HOCs wrap a component and inject additional props or behavior, while render props involve passing a function as a prop that returns JSX, giving fine-grained control over what is rendered. HOCs are more declarative but can lead to nested wrappers, whereas render props provide explicit control but may result in more verbose code. Both enable reusable, composable components but differ in syntax and flexibility.

The useMemo hook memoizes the result of a computation, recalculating the value only when its dependencies change. This optimization avoids expensive recalculations on every render, improving performance particularly in components with heavy computations or frequent updates.
1250. What is useMemo and when should you use it?
Category: Hooks
You should use useMemo when you have expensive computations or complex calculations inside your functional components that don’t need to run on every render. By memoizing the output, it ensures the computation only reruns when its dependencies change, leading to more efficient rendering.
1251. What is useReducer and how does it compare to useState?
Category: Hooks
useReducer is a hook used for managing more complex state logic compared to useState. While useState handles simple state updates, useReducer uses a reducer function to manage state transitions, making it ideal for state with multiple sub-values or when next state depends on previous state logic.
1252. What is useRef and how is it different from state?
Category: Hooks
The useRef hook provides a mutable container whose value persists across renders but updating it does not trigger re-renders, unlike state managed by useState. It is ideal for storing values like DOM references or mutable variables that don’t affect rendering logic.
1253. What is useRef and how is it used?
Category: Hooks
useRef is used to create a persistent mutable reference in functional components. It’s commonly used to access or manipulate DOM elements directly, store values that should survive re-renders, or hold previous state values without causing additional renders.
1254. What is useState and how is it used?
Category: Hooks
The useState hook allows functional components to have state variables. It returns a state value and a setter function to update that state. When the setter is called, React schedules a re-render to update the UI with the new state.
1255. What is Zustand and how does it compare to Redux?
Category: State Management
Zustand is a lightweight and simple state management library for React. Compared to Redux, it requires less boilerplate, uses hooks for direct state access, and has a more minimal API, making it easier and faster to implement while still supporting scalable global state.
1256. What libraries can be used for i18n in React?
Category: Internationalization
There are several popular libraries for internationalization (i18n) in React. The most widely used is react-i18next, which offers powerful translation capabilities, support for namespaces, and seamless integration with React hooks and context. These libraries help manage translations, locale detection, and formatting to make applications accessible to users worldwide.
1257. What libraries can help with form handling in React?
Category: Forms
Several libraries simplify form handling in React by managing state, validation, and submission processes. Formik is one of the most popular options, providing easy integration with Yup for schema validation and supporting both controlled and uncontrolled components. React Hook Form leverages React hooks for performant and minimal re-renders, making it lightweight and fast. Other options include Redux Form for integration with Redux, though it is less commonly used now due to performance considerations, and Final Form, which offers flexibility and a simple API for form management.
1258. What libraries help with form management?
Category: Forms
To manage forms effectively in React, developers often rely on libraries such as Formik, which provides declarative form handling and validation support. React Hook Form is favored for its hook-based approach, minimal re-renders, and ease of use with native HTML inputs. Final Form and its React wrapper, React Final Form, provide powerful subscription-based form state management. These libraries reduce boilerplate and improve maintainability for complex forms.
1259. What lifecycle methods correspond to error boundaries?
Category: Advanced Concepts
Error boundaries in React are implemented using specific lifecycle methods in class components. The primary methods are static getDerivedStateFromError(error), which updates state to indicate an error has occurred, and componentDidCatch(error, info), which logs the error or performs side effects such as reporting. These methods allow components to gracefully handle errors during rendering, lifecycle methods, or in constructors of child components, preventing the entire app from crashing.
1260. What rules must hooks follow?
Category: Hooks
Hooks in React must follow two fundamental rules: (1) They should only be called at the top level of React function components or custom hooks, never inside loops, conditions, or nested functions to preserve consistent hook ordering. (2) They must only be called from React function components or custom hooks, not from regular JavaScript functions. These rules ensure React can correctly track hook calls and manage state and effects reliably.

1263. What’s the difference between React elements and components?
Category: Core Concepts
React elements are the smallest building blocks in React — they are plain objects that describe what you want to see on the screen, such as HTML tags or other React components. Think of elements as the instructions for React to create DOM nodes. Components, on the other hand, are reusable functions or classes that return React elements. Components define the structure, behavior, and appearance of UI sections and can be composed to build complex interfaces. Essentially, elements are the output of components, and components control what elements are rendered.
1264. When should you create a custom hook?
Category: Hooks
Custom hooks should be created when you need to extract and reuse logic involving React state or lifecycle features across multiple components. If you find yourself repeating similar useEffect, useState, or other hook patterns in different places, packaging that logic into a custom hook promotes modularity and reduces duplication. Custom hooks enable clean abstractions for complex behaviors like data fetching, subscriptions, or form handling, making your code more maintainable and readable.
1265. When should you use useReducer over useState?
Category: Hooks
You should use useReducer instead of useState when your component state logic is complex, involves multiple sub-values, or when the next state depends on the previous one. useReducer centralizes state updates into a reducer function, making state transitions predictable and easier to manage, especially for forms, complex user interactions, or deeply nested state. It also helps when you want to optimize performance by preventing unnecessary re-renders via dispatching actions.
1266. Why are keys important in React lists?
Category: Lists & Keys
Keys are essential in React lists because they help React identify which items have changed, been added, or removed. This identification allows React to optimize rendering by only updating the parts of the DOM that actually changed, rather than re-rendering the entire list. Keys must be unique and stable to maintain consistent identity across renders, ensuring smooth UI updates and preventing bugs caused by incorrect element reuse.
1267. Why can’t error boundaries catch errors inside event handlers?
Category: Error Handling
Error boundaries only catch errors that occur during rendering, lifecycle methods, and constructors of child components. They do not catch errors inside event handlers because event handlers run asynchronously outside of the rendering phase. To handle errors in event handlers, you need to use regular JavaScript try-catch blocks or other error handling logic within the event function itself.
1268. Why is immutability important in React state management?
Category: Core Concepts
Immutability is crucial in React state management because it enables efficient change detection. By ensuring that state objects are not mutated directly but instead replaced with new copies, React can quickly determine what changed by comparing references. This process supports React's reconciliation algorithm, leading to optimal re-rendering and predictable application behavior. Immutability also helps avoid unintended side effects and makes debugging easier.
1269. Why were Hooks introduced in React?
Category: Hooks
Hooks were introduced in React to address the limitations of class components, such as complex lifecycle methods and challenges with code reuse. They allow developers to use state and other React features inside function components, leading to simpler, more readable, and more composable code. Hooks improve logic reuse through custom hooks and reduce the boilerplate associated with classes, promoting better organization and maintainability.

Airflow Q&A - Set 1

1. What is Apache Airflow?

Apache Airflow is an open-source platform to programmatically author, schedule, and monitor workflows. It allows you to define complex workflows as directed acyclic graphs (DAGs) of tasks.

import airflow
from airflow import DAG
from airflow.operators.dummy_operator import DummyOperator
from datetime import datetime

dag = DAG('example_dag', start_date=datetime(2023, 5, 1))

start_task = DummyOperator(task_id='start', dag=dag)
end_task = DummyOperator(task_id='end', dag=dag)

start_task >> end_task

Answer: Airflow is a platform for authoring, scheduling, and monitoring workflows. It allows for the easy construction and management of complex task dependencies.

2. What is a DAG in Airflow?

A Directed Acyclic Graph (DAG) is a collection of tasks with defined dependencies between them. It represents the workflow, where each node is a task, and the edges represent the dependencies between those tasks.

dag = DAG('example_dag', default_args=default_args, schedule_interval='@daily')
task1 = DummyOperator(task_id='task1', dag=dag)
task2 = DummyOperator(task_id='task2', dag=dag)

task1 >> task2

Answer: A DAG is a collection of tasks organized in a way that reflects their dependencies and execution order. It defines the structure of your workflow.

3. What are operators in Airflow?

Operators in Airflow define the work to be performed. There are many types of operators, such as BashOperator, PythonOperator, and DummyOperator, each serving a specific function in task execution.

from airflow.operators.bash_operator import BashOperator

task = BashOperator(
    task_id='bash_task',
    bash_command='echo "Hello World"',
    dag=dag
)

Answer: Operators are used in tasks to define the actions to be performed, such as executing a bash command, running a Python function, or making an HTTP request.

4. What is the difference between a task and a DAG in Airflow?

A task represents a single unit of work that can be executed, while a DAG is a collection of tasks with defined dependencies that need to be executed in a specific order.

dag = DAG('example_dag', start_date=datetime(2023, 5, 1))

task1 = DummyOperator(task_id='task1', dag=dag)
task2 = DummyOperator(task_id='task2', dag=dag)

task1 >> task2

Answer: A DAG is a collection of tasks, while a task is a single operation in the workflow that is executed as part of a DAG.

5. How do you schedule a DAG in Airflow?

You can schedule a DAG by setting the `schedule_interval` parameter. It can be set to a cron expression or a predefined string like `@daily`, `@hourly`, etc.

dag = DAG('example_dag', schedule_interval='@daily', start_date=datetime(2023, 5, 1))

Answer: The `schedule_interval` parameter determines the frequency at which the DAG is triggered. You can use cron expressions or special strings for scheduling.

6. What are Airflow task dependencies?

Task dependencies define the order in which tasks should run. You can set dependencies using the `>>` operator to specify which tasks should run before or after others.

task1 >> task2  # task1 runs before task2
task2 >> task3  # task2 runs before task3

Answer: Task dependencies define the execution order of tasks. By chaining tasks with `>>` or using `set_upstream()` and `set_downstream()`, you can establish dependencies.

7. How can you pass parameters between tasks in Airflow?

You can pass parameters between tasks using XComs. XComs allow tasks to exchange messages, such as passing a value from one task to another.

def push_value(**kwargs):
    value = 'some value'
    kwargs['ti'].xcom_push(key='my_key', value=value)

def pull_value(**kwargs):
    value = kwargs['ti'].xcom_pull(key='my_key', task_ids='push_task')
    print(value)

push_task = PythonOperator(
    task_id='push_task',
    python_callable=push_value,
    dag=dag
)

pull_task = PythonOperator(
    task_id='pull_task',
    python_callable=pull_value,
    dag=dag
)

push_task >> pull_task

Answer: XComs (short for "Cross-communication") allow tasks to exchange data. You can push data to XComs in one task and pull it in another.

9. How do you create a custom operator in Airflow?

To create a custom operator, you need to subclass an existing operator (e.g., BaseOperator) and implement the `execute()` method with the specific logic for your task.

from airflow.models import BaseOperator
from airflow.utils.decorators import apply_defaults

class CustomOperator(BaseOperator):
    @apply_defaults
    def __init__(self, param1, param2, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.param1 = param1
        self.param2 = param2

    def execute(self, context):
        print(f'Executing task with {self.param1} and {self.param2}')

custom_task = CustomOperator(
    task_id='custom_task',
    param1='value1',
    param2='value2',
    dag=dag
)

Answer: A custom operator is created by subclassing `BaseOperator` and overriding the `execute()` method to implement the task's specific logic.

100. How do you apply a `catchup` behavior to a DAG in Airflow?

The `catchup` parameter in a DAG determines whether Airflow should backfill the DAG's past runs. Setting it to `False` prevents backfilling for missed runs.

dag = DAG(
    'my_dag',
    default_args=default_args,
    catchup=False  # Disable backfilling
)

Answer: You can control the backfilling behavior of a DAG using the `catchup` parameter. Setting it to `False` will prevent Airflow from backfilling any missed DAG runs.

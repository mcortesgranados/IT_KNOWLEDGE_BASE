QUESTION 1

Why would you use Transit Gateway over VPC peering?


VPC peering causes networking bottlenecks.


VPC peering isn't as secure as Transit Gateway.


Transit Gateway works across regions where VPC peering doesn't.

CORRECT
You have too many VPCs to reasonably peer together.

Sorry!
This is not true, as Transit Gateway is designed for when you have too many VPCs to peer together. Reference Documentation: Transit Gateway (https://aws.amazon.com/transit-gateway/)

Correct Answer
Transit Gateway is designed for when you have too many VPCs to peer together. Transit Gateway has: easy connection of thousands of VPCs, support for hybrid connectivity (VPN and Direct Connect connections), centralized routing configuration, and low operational costs. VPC peering has: lower overall cost, no bandwidth limits, lower latency, security group compatibility with intra-Region VPC peering. Reference Documentation: Transit Gateway (https://aws.amazon.com/transit-gateway/)

QUESTION 5

What is the purpose of a NAT gateway?


To act as a firewall for your resources


To forward traffic to other EC2 instances

CORRECT
To forward traffic from private subnets to services outside your VPC


To block malicious traffic from leaving your network

Sorry!
NAT gateways allow instances in a private subnet to connect to services outside your VPC. Reference: NAT Gateways (https://docs.aws.amazon.com/vpc/latest/userguide/vpc-nat-gateway.html)

Correct Answer
A NAT gateway is a Network Address Translation (NAT) service. You can use a NAT gateway so that instances in a private subnet can connect to services outside your VPC but external services cannot initiate a connection with those instances. Reference: NAT Gateway (https://docs.aws.amazon.com/vpc/latest/userguide/vpc-nat-gateway.html)

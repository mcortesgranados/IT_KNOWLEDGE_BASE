So what is Amazon ECR?
Well it's a managed container image registry
service that is secure, scalable, and reliable.
It supports private repositories
with resource-based permissions using AWS IAM.
It allows you to push images that are either
Open Container Initiative Images, or OCI, Docker images,
or even OCI artifacts,
so there's several supported formats.
So what components should you know for the exam?
Well, the first is a registry.
A private registry is provided to each AWS account.
It's regional, and you create 1 or more for image storage.
Now, to authenticate to your registry,
you need an authentication token that authorizes you
to push and pull images to or from your registries.
Now, within your registry, you have repositories,
and these contain all of your Docker images, OCI images,
and OCI artifacts that we talked about.
And what's cool is each repository has a policy,
so you can control all access to repos and images
on a per-repository basis.
And the last thing you should know here is an image,
so any container image that you push or pull
to and from your repository itself.
Now a thing to call out is that Amazon ECR Public
is a similar service,
but it's used for public image repositories,
as opposed to private.
So let's move on to features that you should know.
The first one we'll look at is lifecycle policies,
and these essentially help management
of images in your repositories.
You define rules for cleaning up images that are unused.
And a cool thing about this is
that you can actually test your rules before you apply them,
so you can see which images are going to be removed
before you actually run it.
It also offers what is known as image scanning.
So this actually helps identify software vulnerabilities
that live within your container images,
so it's a security feature.
Repositories can actually be set up to scan on push,
so whenever you push an image to a repo,
Amazon ECR can actually go through, scan it,
and then generate reports.
And the cool thing about the reports
is you can retrieve those results
for the scans of each image.
You can see where some vulnerabilities live
or why it was flagged for some type of software insecurity.
Now let's also talk about sharing.
Since sharing is caring, Amazon ECR does allow
for cross-region support, cross-account support,
and these are both configured per repository and per region,
so keep that in mind.
Remember, each registry is regional for each account.
The next thing we have is cache rules.
So you can set pull through cache rules that allow
for caching public repos privately.
So essentially, Amazon ECR will periodically reach out
to a public repo and check the current caching status
for your private version.
So it makes sure things are up to date,
and you don't have to pull publicly
and then privately to do so.
It does it all for you.
The next big thing here is tag mutability.
So what this does is it prevents image tags
from being overwritten,
so you won't accidentally overwrite a versioned tag
for a particular image.
And to configure this, you do so on a per-repository level.
So each repository can have this on or off.
And that's going to do it for the features to know.
Let's move on to integrations.
So what services does Amazon ECR integrate with?
What's cool about this service is it will integrate
with your own container infrastructure if you want to.
So if you own and run your own Docker infrastructure
on-premises, you can still use Amazon ECR.
But better yet, it does integrate tightly with Amazon ECS.
So you can use your images
in ECS container definitions very easily.
It also integrates with, not surprisingly, Amazon EKS.
Again, you can pull images for your EKS clusters.
And then lastly, there's a thing
called Amazon Linux containers that can be used locally
for software development.
Now the first 3 are the big ones you'll want to know.
The last one is just a little bit of extra information.
So let's go ahead and wrap things up with some exam tips.
You need to understand
that this is a container image storage service,
and it's AWS managed.
It supports several formats including Docker images,
OCI images, and OCI-compatible artifacts.
You can implement lifecycle policies,
which are rules, on when you should expire
and remove unused or older images.
And you can leverage the security feature of image scanning.
So each repository can be set to scan on push,
which identifies software vulnerabilities
within your images.
You can also set up tag mutability,
which again helps prevent image tags from being overwritten.
Some keywords to look out for on the exam would be things
like a managed container image registry or repository,
anything OCI repository related,
or some type of easy image integration
with Amazon ECS or Amazon EKS.

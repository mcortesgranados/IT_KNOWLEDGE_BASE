So what is AWS Step Functions?
In a nutshell, it's a serverless orchestration service
that is going to allow you to combine AWS Lambda functions
with other AWS services
to build business critical applications.
It provides a graphical console
that you can use to see your applications workflow,
as well as a series of different event-driven steps.
Now, the main components within Step Functions
are known as state machines and tasks.
And we'll cover those here in a little bit.
A state machine is a particular workflow
with different event-driven steps within it.
And a task is a state in a workflow
that represents a single unit of work
that another AWS service will perform for you,
and each step in a workflow is considered a state.
So every single step is a state in a workflow
in AWS Step Functions.
Now, AWS Step Functions have 2 different types
of workflows.
We have standard and we have express.
So let's talk about these different workflows.
Each workflow, like we mentioned, has executions.
And executions are instances where you run your workflows
in order to perform your tasks.
So we have our standard and our express workflows
that we're going to compare.
Standard workflows have an exactly-once execution.
It's also good to know that these type of workflows
can actually run for up to one year.
Yeah, you read that right and you heard that right.
One whole year.
They're very useful because of this,

A big number to keep in mind

Now, express workflows are slightly different.

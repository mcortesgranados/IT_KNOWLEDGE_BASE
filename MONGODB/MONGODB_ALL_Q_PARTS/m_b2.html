What is the MongoDB aggregation pipeline and how does data flow through it?

The aggregation pipeline is a server-side framework that passes documents through an ordered sequence of stages, similar to a Unix pipe. Each stage receives the document stream produced by the previous stage, transforms it, and emits zero or more documents to the next stage. Stages can filter, reshape, group, join and compute new values, so the final output is whatever the last stage emits.

db.orders.aggregate([
  { $match: { status: "paid" } },
  { $group: { _id: "$customerId", total: { $sum: "$amount" } } }
])

In what order do the stages of an aggregation pipeline execute?

Stages execute in the exact order they appear in the array; the optimizer may merge or move some stages internally, but the visible semantics follow array order. A few stages have positional rules: $out and $merge must be the last stage, and $geoNear must be the first. $text is only allowed inside a $match that is the first stage of the pipeline.

Why does stage order matter so much for pipeline performance?

Each stage processes whatever volume the previous stage produced, so filtering and projecting early keeps later stages cheap. Putting $match and a selective $sort first also lets MongoDB use indexes and avoid a blocking in-memory sort. A pipeline that groups or unwinds before filtering can do far more work than necessary.

What does the $match stage do and where should you place it?

$match filters documents using the same query syntax as find(), so operators such as $gt, $in and $elemMatch all work. It should normally be the first stage so that the query planner can use indexes and the smallest possible document set flows downstream. It can also appear later to filter intermediate results after a $group or $unwind.

{ $match: { status: "shipped", amount: { $gte: 100 } } }

How is $match in an aggregation different from a find() filter?

Both use the same query operators, but $match cannot use projection options, hints or $where style JavaScript, and it must be a plain query document. $match also cannot contain aggregation expressions such as $expr comparisons directly unless they are wrapped in $expr. Unlike find(), the output of $match continues into further stages rather than being returned to the client.

What does $project do and how do you include or exclude fields?

$project reshapes each document by keeping, dropping or adding fields. Use field: 1 to include and field: 0 to exclude; _id is included by default and must be explicitly excluded with _id: 0. You cannot mix inclusions and exclusions in one specification, except for the _id field.

{ $project: { name: 1, "address.city": 1, _id: 0 } }

How do you create a computed field with $project?

Assign an expression instead of 0 or 1, and the field is replaced by the expression result. Expressions can combine operators, literals, field paths and variables, which makes $project useful for unit conversion, string formatting and null handling. In MongoDB 8.x you may also use the shorter { field: "$other" } style aliasing on its own.

{ $project: { total: { $multiply: ["$price", "$qty"] }, label: { $toUpper: "$sku" } } }

What is the difference between $project and $addFields?

$addFields adds or overwrites fields while keeping every other field in the document, whereas $project requires you to list what you keep. $addFields is therefore safer when the document shape should stay mostly intact. $set is an exact alias of $addFields.

What does $group do and what is the _id field used for?

$group collapses documents that share the same grouping key into one document per key. The _id field of the output holds the grouping expression, such as a field path, a document of several fields or null for a single global group. All other output fields must be produced by accumulators.

{ $group: { _id: { country: "$country", year: { $year: "$createdAt" } }, n: { $sum: 1 } } }

How do $sum and $avg behave when values are missing or non-numeric?

Both accumulators ignore missing values and values that are not numeric, such as strings or arrays. $sum returns 0 when no numeric value is available, while $avg returns null because it has nothing to divide by. Wrap values in $ifNull or $toDouble if you need a specific fallback behaviour.

When should you use $push instead of $addToSet inside $group?

$push appends every value in encounter order and keeps duplicates, so it preserves the original sequence. $addToSet keeps only distinct values, which removes duplicates but gives no ordering guarantee and costs more memory on large groups. Use $addToSet for tag-like data and $push when order or repetition matters.

{ $group: { _id: "$sku", tags: { $addToSet: "$tag" } } }

How do the $min and $max accumulators work?

$min and $max compare values across the documents in each group and keep the smallest or largest one. Comparison follows BSON type ordering, so numbers are compared with numbers and strings with strings. They can also be applied to expressions or documents, and $min is frequently used to find the earliest date in a group.

How do you count documents per group in an aggregation?

Add a field accumulated with { $sum: 1 }, which increments by one for every document in the group. Using { $sum: "$field" } would add the field values instead of counting documents, and would return 0 if the field is missing. The resulting field is a normal output field that can be renamed or sorted on.

{ $group: { _id: "$status", count: { $sum: 1 } } }

What does $sort do and how do you sort on several fields?

$sort orders the stream by one or more fields using 1 for ascending and -1 for descending. Multiple keys are evaluated left to right, so the first field is the primary order and later fields break ties. Sorting is a blocking operation unless an index can supply the requested order.

{ $sort: { country: 1, revenue: -1 } }

What does $limit do and why is it usually paired with $sort?

$limit passes only the first N documents of the stream and discards the rest. After a $sort it returns a top-N result, which the engine can compute with a bounded in-memory sort instead of sorting the whole set. Placing $limit before $sort returns arbitrary documents and then sorts only those, which is rarely what you want.

What does the $unwind stage do?

$unwind takes an array field and emits one output document per array element, copying all other fields into each copy. The element itself can be exposed through includeArrayIndex or referenced with $field afterwards. It is the standard way to flatten arrays before grouping on element values.

{ $unwind: { path: "$items", includeArrayIndex: "idx", preserveNullAndEmptyArrays: true } }

What happens to a document when $unwind encounters an empty array?

By default the document is dropped, because an empty array produces zero output documents. Missing or null array fields are also dropped by default. Set preserveNullAndEmptyArrays: true to keep the document once with the array field missing.

What do preserveNullAndEmptyArrays and includeArrayIndex control in $unwind?

preserveNullAndEmptyArrays keeps documents whose array is missing, null or empty, so counts are not silently reduced. includeArrayIndex adds a field holding the zero-based position of each element, which is useful for ordering or reconstructing the array. It is a common source of inflated document counts when forgotten.

What is $lookup and which parameters does it require?

$lookup performs a left outer join with another collection in the same database, matching each input document to foreign documents. The shorthand form needs from, localField, foreignField and as, where as names the array of matched documents. Documents with no match still appear, with an empty array.

{ $lookup: { from: "customers", localField: "customerId", foreignField: "_id", as: "customer" } }

Why does $lookup need an index and how expensive is it?

The join runs one query per input document against the foreign collection, so an index on the foreignField is essential; without it each lookup becomes a collection scan. Cost therefore scales with the number of input documents times the per-lookup cost. Filtering the input with an early $match is the most effective optimization.

What does $addFields do to the existing document?

It returns each input document with new fields added or existing fields overwritten, leaving all other fields untouched. Expressions may reference existing fields, and dotted paths create nested fields. It is usually preferred over $project when only a couple of derived values are needed.

How do you remove fields in an aggregation pipeline with $unset?

$unset takes a field, a list of fields or an array of field names and removes them from every document. It is shorthand for a $project that excludes those fields. Removing sensitive fields such as password hashes early keeps them from reaching later stages and the client.

{ $unset: ["passwordHash", "internalNotes"] }

What does the $count stage return?

$count replaces the stream with a single document of the form { count: n }, where the field name is the argument you supply. It is equivalent to a $group with $sum: 1 plus a $project. An empty input produces no document at all, so clients must handle a missing result.

What is $facet and when would you use it?

$facet runs several independent sub-pipelines over the same input documents and returns one document with an array per facet. It lets a single pass produce, for example, paginated results plus total counts plus category breakdowns. Sub-pipelines cannot use $out, $merge or $facet themselves, and the input set is buffered in memory.

{ $facet: { data: [{ $skip: 0 }, { $limit: 10 }], total: [{ $count: "n" }] } }

What is the $bucket stage and which options does it need?

$bucket groups documents into ranges defined by boundaries, which must be an ascending list of at least two values. It requires groupBy and optionally accepts default for values outside all ranges plus an output document of accumulators. Without a default, documents outside the boundaries raise an error.

{ $bucket: { groupBy: "$amount", boundaries: [0, 50, 100, 500], default: "other", output: { n: { $sum: 1 } } } }

What does $sortByCount do and what is it shorthand for?

$sortByCount groups by an expression, counts documents per value and sorts the result by count descending. It is shorthand for $group on the expression with $sum: 1 followed by $sort: { count: -1 }. It is handy for quick value distributions during exploration.

What is $replaceRoot and how does $replaceWith differ?

$replaceRoot promotes a document-valued expression to be the new top-level document via the newRoot option. $replaceWith is the newer, shorter syntax that takes the expression directly, so $replaceRoot: { newRoot: X } equals $replaceWith: X. The expression must evaluate to a document or the stage fails.

{ $replaceWith: { $mergeObjects: ["$customer", "$$ROOT"] } }

How does $ifNull work in an expression?

$ifNull returns the first argument unless it is null or missing, in which case it returns the second. In MongoDB 8.x it accepts multiple input expressions and returns the first non-null one. It is the standard way to give defaults to optional fields.

{ $project: { phone: { $ifNull: ["$mobile", "$landline", "unknown"] } } }

How does the $cond operator work?

$cond evaluates a boolean expression and returns one of two values, either in array form [if, then, else] or with named fields if, then, else. It is the basic if/else of aggregation and can be nested. The condition must evaluate to a boolean, so wrap comparisons explicitly.

{ $project: { tier: { $cond: [{ $gte: ["$total", 100] }, "gold", "standard"] } } }

How does $switch differ from nested $cond?

$switch evaluates a list of branches and returns the value of the first branch whose case is true, falling back to default. It reads more clearly than deeply nested $cond expressions for multi-way logic. If no branch matches and no default is given, the stage raises an error.

{ $switch: { branches: [
  { case: { $lt: ["$n", 10] }, then: "small" },
  { case: { $lt: ["$n", 100] }, then: "medium" } ],
  default: "large" } }

How do you concatenate strings in an aggregation?

$concat joins any number of string expressions and returns null if any argument is null or missing. Use $ifNull or $toString first when fields are optional or numeric. For joining array elements with a separator, use $reduce combined with $concat.

{ $project: { full: { $concat: ["$firstName", " ", "$lastName"] } } }

How do $substrCP and $substrBytes differ?

$substrCP counts characters, meaning Unicode code points, while $substrBytes counts raw UTF-8 bytes. For text containing accents, emoji or CJK characters, byte indexing can split a character and produce invalid output, so $substrCP is the safer choice. Negative lengths are treated as an error, and out-of-range offsets return an empty string.

What do $toUpper and $toLower do, and can they give case-insensitive matching?

$toUpper and $toLower change the case of a string expression, but they only handle ASCII characters reliably. They cannot use an index, so applying them to a field forces per-document evaluation. For real case-insensitive queries, a collation with strength 1 or 2 on the index and the query is the correct tool.

How do you extract the year or month from a date field?

Date part operators such as $year, $month, $dayOfMonth and $hour take a date expression and return an integer. They accept a timezone document so results respect a local calendar rather than UTC. For very large datasets, $dateTrunc on a pre-grouped bucket is more efficient than extracting parts.

{ $project: { y: { $year: { date: "$createdAt", timezone: "America/Bogota" } } } }

What does $dateToString do and which format specifiers are common?

$dateToString formats a date into a string using a pattern, with optional timezone and onNull settings. Common specifiers include %Y for the four-digit year, %m for the month, %d for the day and %H:%M:%S for time. It is typically used to build daily or monthly report keys.

{ $project: { day: { $dateToString: { format: "%Y-%m-%d", date: "$createdAt", timezone: "UTC" } } } }

What does $dateTrunc do and why is it useful for reporting?

$dateTrunc truncates a date to a given unit such as hour, day or month, returning a date value rather than a string. Because the output is still a date, results can be sorted, compared and indexed normally. It is the recommended way to build time buckets for charts and rollups.

Which arithmetic operators are available in aggregation expressions?

Basic operators include $add, $subtract, $multiply, $divide, $mod, $abs, $ceil, $floor and $round, plus $pow and $sqrt. $add also concatenates when one operand is a date, which makes it useful for date arithmetic. Division by zero raises an error, so guard the divisor.

What does the $filter operator do?

$filter returns a new array containing only the elements that satisfy a condition, using input, cond and an optional as variable name. The default element variable is $$this. It is the array equivalent of a $match and is often used to trim embedded arrays before returning documents.

{ $project: { active: { $filter: { input: "$items", as: "i", cond: { $eq: ["$$i.active", true] } } } } }

What does the $map operator do?

$map applies an expression to every element of an array and returns an array of the results, preserving order and length. It accepts input, as and in. Use it to transform a field inside each array element, for example extracting only product codes.

{ $project: { codes: { $map: { input: "$items", as: "i", in: "$$i.sku" } } } }

What does $reduce do and when is it needed?

$reduce folds an array into a single value by iterating with an accumulator, exposing $$value and $$this in the in expression. It is required for operations like summing array elements, flattening nested arrays or concatenating strings with separators. initialValue defines the starting accumulator.

{ $project: { total: { $reduce: { input: "$items", initialValue: 0,
  in: { $add: ["$$value", "$$this.price"] } } } } }

How do you get the number of elements in an array during aggregation?

$size returns the length of an array expression. It raises an error if the value is missing or not an array, so guard it with $isArray and $ifNull on optional fields. In a plain query, $size can only match an exact length inside $expr.

How does $slice behave in aggregation compared with projection?

In a find() projection, $slice trims the returned array to the first or last N elements without changing anything else. In aggregation, $slice is an expression that takes an array, a start position and an optional count, and can return a middle subrange using a negative count. The aggregation form can be combined with other expressions, while the projection form cannot.

{ $project: { top3: { $slice: ["$scores", 3] }, last2: { $slice: ["$scores", -2] } } }

What is $expr and when do you need it in a query?

$expr lets a query filter compare fields of the same document or use aggregation operators inside find(), $match or deleteMany(). Without it, the query language can only compare a field to a constant. $expr cannot use indexes as efficiently in all cases, so keep it simple and test with explain().

db.orders.find({ $expr: { $gt: ["$shippedQty", "$orderedQty"] } })

What is $$ROOT and when do you use it?

$$ROOT references the current top-level document as it enters the stage, which is useful for preserving the original document while reshaping. It is commonly used with $mergeObjects to flatten a subdocument into the root, or with $push to collect whole documents per group. Be aware it holds the full document, so pushing it into an array for many documents can hit memory limits.

{ $group: { _id: "$status", docs: { $push: "$$ROOT" } } }

How do let variables work inside an aggregation stage?

A let option defines variables that are evaluated once in the stage context and referenced with the double-dollar prefix, for example $$minTotal. Inside $lookup pipelines this is how a local field is passed into the sub-pipeline. Referencing an undefined variable is an error, and variables are scoped to the stage that declares them.

{ $lookup: { from: "orders", let: { cid: "$_id" },
  pipeline: [{ $match: { $expr: { $eq: ["$customerId", "$$cid"] } } }],
  as: "orders" } }

What does $out do and how does it differ from $merge?

$out writes the pipeline result to a collection, atomically replacing the target collection as a whole. $merge instead inserts, updates or leaves existing documents, so it can incrementally refresh a target. $out is simpler but rebuilds everything, while $merge supports incremental materialized views and can keep existing documents.

Which restrictions apply to the $out stage?

$out must be the last stage of the pipeline and writes only to a collection in the same database. It replaces the target collection, so any indexes previously defined on the target are lost and must be recreated. It cannot write to a view, and it does not create a new database.

What does $merge require to work correctly?

$merge needs a target collection and an on field that identifies matching documents; the default is _id, and that field must have a unique index. You also choose behaviour with whenMatched and whenNotMatched, and can target a different database. If more than one target document matches, the stage fails, which is exactly what the unique index prevents.

{ $merge: { into: "daily_sales", on: "_id",
  whenMatched: "merge", whenNotMatched: "insert" } }

How would you build an on-demand materialized view with $merge?

Run the aggregation that computes the summary and finish it with $merge into a dedicated collection, using whenMatched: "merge" so reruns update the rows. The target collection can then be indexed and queried cheaply, unlike a normal view which recomputes on every read. Applications or a scheduled job decide when to refresh the summary.

What happens when an aggregation pipeline exceeds its memory limit?

Blocking stages that must buffer data are limited to 100 MB per stage by default. Exceeding that limit fails the operation with a memory limit error instead of degrading silently. You either make the pipeline more selective or enable disk use explicitly.

What does allowDiskUse do and where can you enable it?

allowDiskUse: true lets blocking stages spill temporary files to disk when they exceed 100 MB of memory. You can pass it as an option to aggregate(), and in MongoDB 8.x find() also accepts it for large sort operations. Spilling prevents failures but is much slower, so it is a safety valve rather than a design goal.

db.orders.aggregate(pipeline, { allowDiskUse: true })

Which stages are most likely to hit the memory limit?

$group and $sort are the classic blockers because they must see many documents before emitting results. $bucket, $facet and $unwind followed by $group can also consume a lot of memory. Reducing input with an early $match and avoiding $push: "$$ROOT" are the usual fixes.

How does the aggregation optimizer use indexes?

The planner can push a leading $match and a following $sort into a single indexed query plan, so the index both filters and orders documents. It can also cover a pipeline when all needed fields are in the index. Once a stage changes document shape, such as $project or $group, later stages generally cannot use collection indexes.

How do you check whether an aggregation used an index?

Run the pipeline with explain("executionStats") and inspect the winning plan, looking for IXSCAN versus COLLSCAN and the number of documents examined. totalKeysExamined close to nReturned indicates a selective index. Metrics such as hasSortStage tell you whether an in-memory sort was needed.

db.orders.explain("executionStats").aggregate([
  { $match: { status: "paid" } },
  { $sort: { createdAt: -1 } },
  { $limit: 20 }
])

How do you create a text index and search with $text?

Create a text index on one or more string fields with the "text" type, then query with the $text operator and a $search string. $text performs tokenized, stemmed word matching rather than exact substring matching. You can sort by textScore to rank results by relevance.

db.articles.createIndex({ title: "text", body: "text" });
db.articles.find({ $text: { $search: "mongodb index" } },
  { score: { $meta: "textScore" } }).sort({ score: { $meta: "textScore" } });

What are the main limitations of a text index?

A collection can have only one text index, though that index may cover several fields. $text must appear inside a $match that is the first stage of a pipeline, and it cannot be combined with hint. Text indexes ignore stop words and stem terms, so exact substring or partial-word searches are not supported.

How do you search for an exact phrase or exclude a term with $text?

Wrap the words in double quotes inside the search string to require them as a phrase, and prefix a term with a minus sign to exclude it. Terms separated by spaces are OR-ed by default unless you quote them. This is why "data modeling" -mysql behaves as a phrase match with an exclusion.

db.articles.find({ $text: { $search: "\"data modeling\" -mysql" } })

What is a 2dsphere index used for?

A 2dsphere index supports queries on GeoJSON geometries and legacy coordinate pairs on a spherical model of the Earth. It enables proximity, intersection and containment queries on points, lines and polygons. The indexed field must contain valid GeoJSON, for example a Point with a coordinates array of longitude then latitude.

db.stores.createIndex({ location: "2dsphere" });

What does $near do and what does it require?

$near returns documents ordered by distance from a point, nearest first, optionally limited by $minDistance and $maxDistance in meters. It requires a geospatial index on the queried field and cannot be used inside an aggregation $match; use $geoNear there. Because results are already sorted by distance, adding your own sort is unnecessary.

db.stores.find({ location: { $near: { $geometry: { type: "Point", coordinates: [-74.07, 4.65] },
  $maxDistance: 2000 } } })

How does $geoWithin differ from $near?

$geoWithin selects documents whose location lies inside a given shape such as a polygon, circle or box, and returns them in unspecified order. $near selects by distance and returns documents sorted nearest first. $geoWithin does not require sorting, which makes it cheaper when you only need membership in an area.

What is a TTL index and how does expiration work?

A TTL index is a single-field index on a date or array of dates created with expireAfterSeconds. A background task runs roughly every 60 seconds and deletes documents whose indexed date is older than the configured age. Expiration is therefore not exact and deletions are not guaranteed immediately.

db.sessions.createIndex({ lastSeen: 1 }, { expireAfterSeconds: 3600 });

Which restrictions apply to TTL indexes?

The indexed field must be a date or an array of dates, and the index must be single-field, so it cannot be part of a compound index. The TTL monitor only removes whole documents, so expiring embedded array elements requires application logic or a capped or time series design. Changing the retention period means using collMod rather than rebuilding the index.

What is a capped collection?

A capped collection is a fixed-size collection that keeps documents in insertion order and overwrites the oldest documents when full. Inserts are very fast and reads in natural order are sequential, which suits logs and queues. The size is declared at creation and cannot be changed without recreating the collection.

db.createCollection("logs", { capped: true, size: 10485760, max: 100000 });

What are the limitations of capped collections?

Documents cannot be deleted individually and updates may not increase document size, so they are unsuitable for mutable data. Only the natural order is guaranteed, and you cannot shard a capped collection. MongoDB itself uses one internally for the replica set oplog, which is the classic example of their append-only use case.

What is a time series collection?

A time series collection is a specialized collection type that stores measurements with a timestamp and optional metadata, and internally groups them into buckets. This bucket structure reduces storage and index overhead compared with one document per measurement. It is intended for metrics, sensor data and event streams that are written once and queried by time range.

db.createCollection("weather", { timeseries: { timeField: "ts",
  metaField: "sensor", granularity: "minutes" } });

What are timeField, metaField and granularity in a time series collection?

timeField names the field holding the date of each measurement and is required. metaField optionally names a field that identifies the series source, such as a sensor id, and is used for grouping and bucketing. granularity tells the server the expected interval between measurements so buckets can be sized efficiently.

What should you know about modifying data in a time series collection?

Updates and deletes are supported but restricted: a delete must match on the metaField and time range, and updates cannot change the time field. Inserting documents with mixed shape in the same series can create many small buckets. Plan retention with TTL on the time field rather than manual deletes where possible.

What is GridFS and when should you use it?

GridFS is a specification, implemented by drivers, for storing files larger than the 16 MB document limit. It splits a file into chunks and stores metadata separately, so the file can be read in parts. Use it for large binaries such as videos or backups; small files are usually better stored in a normal document or an external object store.

Which collections does GridFS use and how large are the chunks?

GridFS stores metadata in fs.files and binary chunks in fs.chunks, with an index on the files id and chunk number. The default chunk size is 255 KB, and it can be configured per bucket. Reads reassemble chunks in order, so range requests still fetch whole chunks.

What is a MongoDB view and how do you create one?

A view is a read-only, named query defined by an aggregation pipeline, stored as metadata in the database. Creating one uses db.createCollection(name, { viewOn: ..., pipeline: [...] }) or db.createView(). Clients query it like a collection, which lets you expose a filtered or reshaped projection without duplicating data.

Are views materialized, and how do you create an on-demand materialized view?

Standard views are computed on every read and consume no storage, so they are only as fast as their underlying pipeline. To materialize results, end a pipeline with $out or $merge into a real collection and query that collection instead. The trade-off is that the data is only as fresh as the last refresh, which you schedule yourself.

What is collation and how do you run a case-insensitive query?

Collation defines language-aware comparison rules for strings, including case and accent handling. To make a query case-insensitive, specify a collation such as { locale: "en", strength: 2 } on the query, and create the index with the same collation so it can be used. The collation must match between index and query or the index is ignored.

db.users.find({ email: "ANA@EXAMPLE.COM" }).collation({ locale: "en", strength: 2 });

What does collation strength control?

Strength sets how many differences are considered significant: 1 ignores case and accents, 2 ignores case but considers accents, and 3, the default, is case and accent sensitive. Higher strengths also consider case variants and, at 4 or 5, punctuation or code point differences. Choose the lowest strength that satisfies the requirement, since it affects index usability.

What is read concern and which levels are commonly used?

Read concern controls the durability and isolation guarantees of data returned by a read. "local" is the default and may return data that could still be rolled back, "majority" returns data acknowledged by most replica set members, and "snapshot" provides a consistent point-in-time view, mainly for transactions. "linearizable" exists for reads that must see all prior majority-acknowledged writes.

What does write concern specify?

Write concern states how many members must acknowledge a write before the driver reports success, using w, plus j for journaling and wtimeout for a bound. w: 1 acknowledges from the primary only and is fast, while w: "majority" survives a failover. Stronger write concern costs latency but reduces the chance of rolled-back writes.

db.orders.insertOne(doc, { writeConcern: { w: "majority", j: true } })

What is a replica set and which roles do its members play?

A replica set is a group of mongod instances that maintain the same data set for redundancy and high availability. Exactly one member is primary and accepts writes, while secondaries replicate the oplog and can serve reads if configured. Elections promote a secondary automatically when the primary becomes unavailable.

What is read preference and which modes exist?

Read preference decides which replica set members a client sends reads to. Modes include primary, primaryPreferred, secondary, secondaryPreferred and nearest. Secondary reads may return slightly stale data, so use primary for read-after-write guarantees.

What are retryable writes?

Retryable writes let the driver automatically retry certain single-document write operations once if a transient network error or failover occurs. MongoDB tracks a session id and transaction number per write so a retried write is applied at most once. They require a replica set or sharded cluster and a supporting write concern, and multi-document operations need a transaction instead.

What is a session and what does causal consistency mean?

A session groups related operations so they share causal ordering metadata, which drivers manage automatically. With causal consistency enabled, a read in the same session is guaranteed to see writes performed earlier in that session, even when reading from a secondary. This is achieved by tracking the operation time and cluster time on the session.

What are change streams?

Change streams let an application subscribe to a real-time stream of data changes on a collection, database or deployment. They emit resume-token-bearing events such as insert, update, replace, delete and invalidate, without tailing the oplog manually. Because they use the oplog, they require a replica set or sharded cluster and majority read concern.

const cs = db.orders.watch([{ $match: { "operationType": "insert" } }]);
while (!cs.isClosed()) { const next = await cs.next(); printjson(next.fullDocument); }

How do you resume a change stream after a disconnect?

Each event includes a _id resume token, which you persist after processing and pass back through resumeAfter when reopening the stream. For an event that was not fully processed, startAfter is the correct option. The oplog window limits how far back a resume can succeed, so long outages can make a token unusable.

What is $jsonSchema validation used for?

$jsonSchema lets you attach a JSON Schema validator to a collection so inserts and updates must match declared field types and required properties. You can add it at creation with validator or later with collMod. Validation happens on write, which protects data quality close to the database rather than only in the application.

db.createCollection("users", { validator: { $jsonSchema: {
  bsonType: "object", required: ["email"],
  properties: { email: { bsonType: "string" } } } } });

What do validationLevel and validationAction control?

validationLevel decides which documents are checked: strict validates all inserts and updates, moderate only validates documents that are already valid, and off disables validation. validationAction decides whether a violation is rejected with error or merely logged with warn. Starting with warn is a safe way to roll out a new schema.

How do you run a multi-document transaction in MongoDB?

Start a session, call startTransaction(), run the operations with that session, then commitTransaction() and end the session. Any error should be followed by abortTransaction(). Transactions require a replica set or sharded cluster and explicit session passing on every operation.

const s = db.getMongo().startSession();
s.startTransaction();
s.getDatabase("shop").orders.insertOne({ _id: 1, total: 10 });
s.commitTransaction();

What are the main limitations of transactions?

A transaction has a default lifetime limit of 60 seconds, controlled by transactionLifetimeLimitSeconds, and each operation must fit within the 16 MB oplog entry limit. Transactions block on conflicting writes, so long-running ones increase lock contention. They are also not a substitute for a good schema; cross-document atomicity is expensive compared with single-document atomic writes.

What is the database profiler and which levels does it support?

The profiler records slow or all operations in the system.profile capped collection for later analysis. Level 0 is off, level 1 records operations slower than slowms, and level 2 records every operation. Level 2 is heavy, so enable it briefly in production and inspect the results with queries on system.profile.

db.setProfilingLevel(1, { slowms: 100 });
db.system.profile.find().sort({ ts: -1 }).limit(5);

What is db.currentOp used for?

db.currentOp() shows operations currently running on the server, including their namespace, duration, plan summary and waiting state. It is the first tool for diagnosing a slow query or a stuck operation in progress. Filter by secs_running or namespace, and use db.killOp() only for operations you are certain are safe to terminate.

db.currentOp({ secs_running: { $gt: 5 }, active: true });

What is the difference between mongostat and mongotop?

mongostat prints a per-second snapshot of server counters such as inserts, queries, updates, deletes, connections and page faults. mongotop reports how much time each collection spends on reads and writes, which points to hot collections. Together they separate overall load from per-collection hotspots.

Which Atlas UI capabilities matter most for day-to-day operations?

The cluster view shows topology, region, tier and connection string, and supports scaling and pausing the cluster. The backup section manages snapshots and point-in-time restores, while alerts can notify on replication lag, slow queries and disk usage. The built-in Performance Advisor and Query Profiler surface slow operations and index suggestions without shell access.

How would you model a one-to-few relationship?

For a small, bounded number of related items, embed them as an array of subdocuments inside the parent, for example a few addresses on a user. This keeps related data in one document, so a single read returns everything and updates stay atomic. The approach works while the array stays small and is not updated concurrently by many writers.

{ _id: 1, name: "Ana", addresses: [ { city: "Bogota" }, { city: "Medellin" } ] }

How would you model a one-to-many relationship?

When the number of children can grow into the hundreds, store the parent id on each child document and index that field, rather than keeping an unbounded array on the parent. Application code queries children by parent id, optionally with pagination. This keeps documents small and avoids rewriting a growing array on every insert.

db.orders.createIndex({ customerId: 1 });
db.orders.find({ customerId: 42 }).sort({ createdAt: -1 }).limit(20);

How would you model a one-to-squillions relationship?

For very high cardinality, such as log lines or sensor readings per device, never embed the children; put the parent reference on the child and index it. The parent document then stays small regardless of volume. Time series collections or bucketing are often a better fit than one document per child for this shape.

How do you decide between embedding and referencing?

Embed when the data is read together, the child count is bounded, and the child has little independent life. Reference when the data is large or unbounded, updated independently, accessed separately, or shared by many parents. Always check the 16 MB document limit and the write pattern, since embedding makes every write rewrite the whole document.

What is the bucket pattern and what problem does it solve?

The bucket pattern groups many small events into one document, typically by time window, storing an array of measurements plus precomputed counts and totals. It dramatically reduces the number of documents and index entries for high-volume time-ordered data. Reads then fetch one bucket instead of hundreds of documents.

{ sensor: "s1", bucketStart: ISODate("2026-01-01T00:00:00Z"),
  count: 60, total: 1432, samples: [ { t: 1, v: 24 }, { t: 2, v: 25 } ] }

What is the computed pattern?

The computed pattern stores a derived value, such as a total, average or count, directly in the document so reads avoid recomputing it. It pays off when reads greatly outnumber writes and the computation is expensive, for example a movie rating average. The trade-off is that the application must update the computed field whenever the underlying data changes.

When does an extended reference go stale, and how do you keep it current?

An extended reference is stale from the moment the source document changes: the copy inside the child keeps the old value until something updates it. The cheap fields to copy are the ones that never change after creation, such as a customer's signup country or a product's SKU prefix. The expensive ones are any field the business can edit, like a name or a price.

Keeping it current needs an explicit writer: either the update path that touches the source also fans out to the copies, or a change stream listener patches them asynchronously. Either way, accept that reads can see a copy a few milliseconds behind, and stamp the embedded block with updatedAt so a background job can find and repair the drift.

Why add a schema version field to documents?

A schemaVersion field records which shape a document follows, so application code can handle several versions during a rolling migration. It makes migrations explicit and lets you find documents that still need upgrading. Without it, distinguishing old and new shapes relies on guessing from missing or present fields.

{ _id: 1, schemaVersion: 2, name: "Ana", fullName: { first: "Ana", last: "Diaz" } }

How do you handle a schema migration in MongoDB?

Either migrate lazily, converting documents as they are read or written, or backfill in batches with a script. Lazy migration spreads the work but requires dual-read code paths; batch migration gives a clean end state but must be throttled. Whichever you choose, deploy application code that understands both shapes before and after the change.

How do you migrate a large collection without downtime?

Process documents in small batches filtered by an indexed field such as _id, update each batch with bulkWrite, and pause between batches to limit load. Track the last processed key so the job can resume after a failure. Run it during low traffic and monitor replication lag and slow queries while it runs.

db.users.find({ _id: { $gt: lastId }, schemaVersion: { $exists: false } })
  .sort({ _id: 1 }).limit(1000);

What is the 16 MB document size limit?

A single BSON document cannot exceed 16 MB, which is a hard limit enforced by the server on insert and update. The limit applies to the encoded BSON, including field names and array elements. Exceeding it fails the write, and no index or option can raise the limit.

What do you do when data no longer fits in one document?

Split the data using the bucket or subset pattern, move large binaries into GridFS, or promote the embedded array into its own collection with a parent reference. Each option trades a single read for smaller documents and more queries. The important step is recognizing the growth trend before writes start failing.

Which compression options does WiredTiger support?

WiredTiger supports snappy, which is the default and favours speed, zlib for better compression at higher CPU cost, and zstd as a balanced option available in current versions. Indexes use prefix compression by default and can also be compressed. The choice affects CPU versus disk usage, not query semantics.

How do you enable or change collection compression?

Pass a WiredTiger storage engine configuration when creating the collection, for example a blockCompressor of zstd. Changing compression on an existing collection requires rewriting its data, typically with an initial sync or a rebuild such as compact or a resync. Verify the effect by comparing storage size and CPU after the change.

db.createCollection("events", { storageEngine: { wiredTiger: {
  configString: "block_compressor=zstd" } } });

How does a multikey index work?

When you index a field that holds an array, MongoDB creates one index entry per array element, and the index is marked multikey. A query on an element value can then use the index without scanning the array. Multikey indexes are larger than scalar indexes and have restrictions on how bounds can be combined.

db.articles.createIndex({ tags: 1 });
db.articles.find({ tags: "mongodb" });

Why can you not create a compound index on two array fields?

Indexing two array fields in the same compound index would produce a cartesian product of index entries for every document, so MongoDB rejects it with a "cannot index parallel arrays" error. The workaround is to index one array field and filter the other in the query, or to restructure the data. A compound index may include at most one array field.

Why is $elemMatch important when querying arrays?

Without $elemMatch, separate conditions on array elements can be satisfied by different elements of the same document. $elemMatch requires a single element to match all conditions, which is usually the intended semantics. It also helps the planner use a multikey index more precisely.

db.orders.find({ items: { $elemMatch: { sku: "A1", qty: { $gte: 2 } } } })

Why is skip and limit pagination slow on large collections?

skip(n) makes the server walk and discard the first n documents, so the cost grows with the page number even when an index is used. Deep pages therefore become progressively slower and put load on the server. It is acceptable for small offsets or admin screens, but not for infinite scrolling.

What is keyset pagination and how does it work?

Keyset pagination remembers the last seen sort value and queries for documents after it, for example { _id: { $gt: lastId } } sorted ascending. Each page costs roughly the same because the index seeks directly to the starting point. Include a unique tiebreaker field so pages cannot skip or repeat documents.

db.orders.find({ createdAt: { $lt: lastDate } }).sort({ createdAt: -1 }).limit(20);

What is the ESR rule for compound indexes?

ESR stands for Equality, Sort, Range: put fields used in equality filters first, then fields used for sorting, then range-filtered fields. This ordering lets the index satisfy the filter and the sort while scanning a contiguous range. Following ESR usually removes the need for an in-memory sort.

db.orders.createIndex({ status: 1, createdAt: -1, total: 1 });

How can an index satisfy a sort?

An index can return documents already ordered if the sort fields form a prefix of the index key pattern and the directions match, either exactly or fully reversed. Equality-constrained leading fields do not break the ordering of the remaining fields. If the sort direction or prefix does not match, the server must perform a blocking sort.

When can a sort not use an index, and what happens then?

A sort cannot use an index when the requested order does not match an index prefix and direction, when the sort is on a computed or unwound field, or when the pipeline has already reshaped documents. The server then performs an in-memory sort, limited to 100 MB per stage unless disk use is allowed. Large blocking sorts are a frequent cause of slow queries and memory errors.

When does a covered query stop being covered?

It stops the moment the planner needs anything the index does not contain. Adding a field to the projection that is not in the index is the usual cause, and so is leaving _id in the results when the index was not built with it. A filter on a field outside the index has the same effect, because the server must fetch the document to test it.

Other quiet breakers: a multikey index where the query has to inspect individual array elements, an $or whose branches use different indexes, and a collation the index was not created with. Check with explain(); if a FETCH stage appears where there was none before, coverage was lost.

How do you confirm that a query is covered?

Run explain("executionStats") and check that the plan has no FETCH stage and that totalDocsExamined is 0. A plan showing only IXSCAN with PROJECTION_COVERED confirms the index answered everything. If totalDocsExamined is greater than zero, the query is not covered.

How does an $or query use indexes?

Each branch of an $or is planned independently and can use its own index, with the results merged and de-duplicated. If any branch cannot use an index, the whole query degrades to a collection scan. That is why an unindexed clause inside $or can make an otherwise fast query slow.

db.users.find({ $or: [ { email: "a@b.com" }, { phone: "+57300" } ] });

When should you use $in instead of $or?

When all values apply to the same field, $in is simpler and lets the planner build a single index scan with multiple bounds. $or is needed when the conditions apply to different fields or contain separate operators. $in also reads more clearly and is easier for the optimizer to handle.

db.orders.find({ status: { $in: ["paid", "shipped"] } });

Why are $ne and $nin often slow?

Negation operators must examine every candidate value to prove that it is not excluded, so they cannot use tight index bounds. With no other selective condition, the server ends up scanning the collection or the whole index. Rewriting the query around positive, selective predicates is usually the fix.

Does $or inside an aggregation $match use indexes?

Yes, a leading $match with $or is planned like the same predicate in find(), so each branch can use an index. The same rule applies: an unindexed branch forces a collection scan. Placing the $or after a stage that reshapes documents removes any chance of index use.

What is the difference between $count in aggregation and countDocuments()?

countDocuments() runs an aggregation with a $match and $group internally, so it returns an accurate count for a filter but scans matching index entries. The $count stage does the same work inside a pipeline. Neither can rely on collection metadata, which is why both can be slow on very large collections with broad filters.

When is estimatedDocumentCount() appropriate?

estimatedDocumentCount() reads collection metadata instead of scanning documents, so it is fast but cannot take a filter. The value can be slightly inaccurate after an unclean shutdown. Use it for dashboards and approximate totals, and use countDocuments() when the number must be exact.

How do you return a page of results together with the total count in one round trip?

Use $facet with one sub-pipeline for the page using $sort, $skip and $limit, and another for the total using $count. Both run over the same filtered input, which saves a second query and guarantees a consistent snapshot. The facet buffers the input, so keep the pre-facet $match selective.

{ $facet: {
  data: [ { $sort: { createdAt: -1 } }, { $skip: 20 }, { $limit: 20 } ],
  meta: [ { $count: "total" } ] } }

How do you produce a value distribution report with counts?

Group by the field and count documents per value, then sort descending by the count; $sortByCount does exactly this in one stage. This gives a quick top-N view of categories, browsers or statuses. Add a $limit afterwards to keep only the most common values.

db.events.aggregate([ { $sortByCount: "$browser" }, { $limit: 10 } ]);

How do you flatten an embedded subdocument into the root?

Use $replaceWith with $mergeObjects combining the subdocument and $$ROOT, so the subdocument fields become top-level fields. The nested copy can then be removed with $unset. This is common before exporting data or feeding a downstream system that expects a flat shape.

{ $replaceWith: { $mergeObjects: ["$address", "$$ROOT"] } },
{ $unset: "address" }

How do you group numeric values into labelled ranges in a pipeline?

Use $switch or nested $cond in a $addFields stage to derive a label, then group by that label. This keeps the range logic explicit and readable compared with deeply nested conditions. For evenly spaced ranges, $bucket is a better fit.

{ $addFields: { band: { $switch: { branches: [
  { case: { $lt: ["$total", 50] }, then: "low" },
  { case: { $lt: ["$total", 200] }, then: "mid" } ], default: "high" } } } }

What is $$NOW and when is it useful?

$$NOW returns the current date and time as a single consistent value for the whole pipeline execution. It is useful for computing ages, retention windows or report periods without sending the timestamp from the client. Because it is evaluated once per operation, all documents are compared against the same instant.

{ $project: { ageDays: { $dateDiff: { startDate: "$createdAt", endDate: "$$NOW", unit: "day" } } } }

What does $$REMOVE do?

$$REMOVE evaluates to a missing value, so assigning it in $addFields or $project removes the field from the output document. It is ideal for conditional exclusion, where a field should disappear only for some documents. It cannot be used to remove fields in a find() projection.

{ $addFields: { internalNote: { $cond: ["$isAdmin", "$note", "$$REMOVE"] } } }

How do you get the latest document per group?

Sort by the timestamp descending before grouping, then take { $first: "$$ROOT" } in the group. The sort must happen before the group, since $first only reflects the incoming order. Sorting ascending and using $last is equivalent but usually less intuitive.

[ { $sort: { createdAt: -1 } },
  { $group: { _id: "$customerId", latest: { $first: "$$ROOT" } } } ]

How do you count distinct values per group?

Collect values with $addToSet and then take $size of the resulting array in a following $project or $addFields. This is a common analytics question because no distinct accumulator exists. The array is held in memory, so for very high cardinality the group can hit the memory limit.

{ $group: { _id: "$country", cities: { $addToSet: "$city" } } },
{ $project: { distinctCities: { $size: "$cities" } } }

How do you rebuild an array after unwinding it?

After $unwind, group by the parent document id and use $push to collect the elements again, ideally after sorting them into the desired order. This is the standard technique for filtering an array and keeping the result as an array. Remember that $push preserves the incoming order, so sort before grouping if order matters.

[ { $unwind: "$items" }, { $match: { "items.qty": { $gt: 0 } } },
  { $group: { _id: "$_id", items: { $push: "$items" } } } ]

How do you avoid running $lookup on every read?

Denormalize the few fields needed at read time using the extended reference or computed pattern, so the common query becomes a single-document read. Keep $lookup for admin views, reports and rare paths where freshness matters more than latency. The cost of denormalization is that changes must be propagated to the copies.

How do you approach reading MongoDB log lines when debugging?

MongoDB writes structured JSON log entries containing a timestamp, severity, component, message id and attributes. Slow operations appear with fields such as planSummary, docsExamined, keysExamined and durationMillis. Filtering on the message id for slow queries and on planSummary: "COLLSCAN" quickly reveals missing indexes.

Select-String -Path mongod.log -Pattern '"planSummary":"COLLSCAN"'

How do you find missing indexes from slow query output?

Look for operations with a high ratio of documents examined to documents returned, and for COLLSCAN in the plan summary. Then inspect the filter and sort fields and design a compound index following the ESR rule. Confirm the improvement with explain("executionStats") rather than assuming.

Can you force an index in an aggregation pipeline?

Yes, aggregate() accepts a hint option naming an index, and the pipeline's leading $match and $sort can then use it. Hints are useful for testing or pinning a stable plan, but they become brittle when data distribution changes. Prefer fixing the index design over hard-coding a hint in production.

db.orders.aggregate(pipeline, { hint: { status: 1, createdAt: -1 } });

Why should a query return only the fields it needs?

Projecting only required fields reduces network payload and memory use on both server and client. It also enables covered queries when the projection matches an index. Returning whole documents by default is convenient in development but costly on wide documents with large arrays.

How do you handle time zones in date aggregation?

Date operators accept a timezone option using an Olson identifier such as America/Bogota, which shifts the calendar calculations to that zone. Without it, grouping by day happens in UTC and produces off-by-hours buckets for local reports. Store dates in UTC and apply the timezone only when grouping or formatting.

How do you match documents whose array contains all specified values?

Use $all with an array of values; it matches only documents containing every listed element. A plain array in the query is treated as an exact match of the whole array, which is usually not what you want. $all can use a multikey index for the elements.

db.articles.find({ tags: { $all: ["mongodb", "indexes"] } });

How do you update a specific element inside an array?

Use $set with the positional $ operator, or arrayFilters with $[elem] when the element is identified by a condition rather than a position. arrayFilters is the reliable choice when several elements could match. Each update rewrites the whole document, so very large arrays are expensive to modify.

db.orders.updateOne({ _id: 1 },
  { $set: { "items.$[i].qty": 5 } },
  { arrayFilters: [ { "i.sku": "A1" } ] });

How do you return only the first matching array element in a find query?

Use a projection with $elemMatch on the array field, which returns just the first element matching the condition. A plain field projection would return the entire array. This keeps responses small for documents with large arrays.

db.orders.find({ _id: 1 }, { items: { $elemMatch: { sku: "A1" } } });

How should monetary values be stored in MongoDB?

Store them as Decimal128 when exact decimal arithmetic is required, or as integer minor units when the application can handle scaling. Binary floating point can introduce rounding errors that are unacceptable for money. Aggregation arithmetic on Decimal128 preserves decimal precision.

{ price: NumberDecimal("19.99"), currency: "COP" }

How do you make a read-modify-write operation atomic?

Use a single-document atomic operator such as findOneAndUpdate with $inc, $set or an update pipeline, instead of reading, modifying in the application and writing back. MongoDB guarantees atomicity per document, so concurrent updates cannot interleave inside that operation. Multi-document atomicity requires a transaction.

db.counters.findOneAndUpdate({ _id: "orders" }, { $inc: { seq: 1 } },
  { returnDocument: "after", upsert: true });

How do you keep only the most recent N items in an array?

Use $push with $each and $slice in an update so the array is trimmed to the newest N elements after insertion. The negative slice count keeps elements from the end of the array. This is a practical way to store a bounded recent-history list without a separate collection.

db.users.updateOne({ _id: 1 },
  { $push: { recentViews: { $each: [ { sku: "A1" } ], $slice: -10 } } });

✅ Before you start

  • A Microsoft account (e.g., an Outlook/Hotmail or Gmail-registered Microsoft account) or a work/school account.
  • An active Azure subscription is recommended if you plan to link Azure DevOps to Azure billing (buy parallel jobs, artifacts, etc.). You can start without one.
  • A modern browser (Edge or Chrome) with internet access.
1

Sign in to Microsoft Azure and pick your account

Everything starts from the Azure portal, since your Azure DevOps organization will be tied to the Microsoft identity (and, optionally, the subscription) you sign in with.

  1. Open a browser and go to https://portal.azure.com. The Microsoft sign-in page opens.
  2. On the “Pick an account” screen, click the account you want to use — in this example, veeduriabg@gmail.com (highlighted in red below).
  3. If your account is not listed, click Use another account and enter your credentials.

Step 1 — Pick the Microsoft account to continue to the Azure portal.

💡 Tip: Use the same account consistently throughout this guide. The Azure DevOps organization you create later will be created under the directory (tenant) of this sign-in.
2

Verify your identity — send a code to your email

Because you are signing in with a personal Microsoft account (such as one registered with a Gmail address), Microsoft asks you to prove your identity with a one-time verification code instead of a classic password prompt.

  1. After selecting your account, the “Get a code to sign in” screen appears, confirming the email the code will be sent to — in this example, veeduriabg@gmail.com.
  2. Click the Send code button (highlighted in red below).
  3. Microsoft emails a short one-time code to that address.
  4. On the next screen, open your email inbox, copy the code, paste/enter it into the verification field, and continue.

Step 2 — Click "Send code" to receive a one-time sign-in code by email.

💡 Tip: The code expires after a few minutes. If it doesn't arrive within a minute or two, check your spam/junk folder, then use the resend option on the verification screen.
3

Retrieve the single-use code from your inbox

Microsoft has emailed the verification code. Now switch to your email provider — in this example, Gmail — to fetch it. Since the sign-in used a Gmail address, the code arrives in the Gmail inbox.

  1. Open a new browser tab and go to https://mail.google.com, signed in with the same account you used for Azure (veeduriabg@gmail.com).
  2. In the inbox, locate the email from “Microsoft account team” with the subject “Your single-use code” (highlighted in red below) — it usually appears within seconds.
  3. Open it and copy the code shown in the body — in this example, 514944.
  4. Return to the Azure sign-in tab, enter the code in the verification field, and continue.
  5. If the email has not arrived after a minute or two, go back to the Azure tab, click resend and try again.

Step 3 — In Gmail, open the "Your single-use code" email from the Microsoft account team.

💡 Tip: The single-use code is valid for a limited time and works only once. Never share it with anyone — Microsoft will never ask you for it by phone or unsolicited email.
4

Open the email and copy the code

The email from the Microsoft account team (account-security-noreply@accountprotection.microsoft.com) contains the one-time code you need to finish signing in.

  1. Open the “Your single-use code” email.
  2. Find the line “Your single-use code is:” — in this example the code is 514944 (highlighted in red below).
  3. Copy the code and switch back to the Azure sign-in tab.
  4. Paste or type the code into the verification field and continue.

Step 4 — The email body shows the single-use code to enter on the Azure sign-in screen.

💡 Tip: As the email itself warns: only enter this code on an official website or app, and don't share it with anyone. If the code has expired by the time you enter it, simply request a new one from the Azure sign-in screen.
5

Confirm the “Stay signed in?” prompt

After the code is accepted, Microsoft asks whether to keep the session open on this device so you won't have to repeat the whole sign-in (and email verification) every time you visit the portal.

  1. On the “Stay signed in?” screen, click Yes (highlighted in red below) — recommended for your own development machine.
  2. Choose No instead if you are on a shared or public computer.
  3. You are then redirected to the Azure portal home dashboard.

Step 5 — Click "Yes" to skip repeated sign-ins on this device.

💡 Tip: Choosing Yes keeps you authenticated on this browser profile, which saves a lot of time while following the rest of this guide. Just avoid it on shared machines.
6

Dismiss the Azure portal welcome tour

The first time you reach the portal, Azure offers a guided tour of the interface. You don't need it for this guide, so you can skip it and go straight to the dashboard.

  1. When the “Welcome to Microsoft Azure” dialog appears (“Let's show you around before you get started”), click Maybe later (highlighted in red below).
  2. Optionally click Start tour instead if you'd like Azure to walk you through the portal basics now — you can always reopen the tour later from the help menu.
  3. The dialog closes and the Azure portal home dashboard is fully visible.

Step 6 — Click "Maybe later" to skip the guided tour and reach the dashboard.

💡 Tip: The tour is purely informational — skipping it changes nothing in your subscription. You can launch it any time from the globe/help icon in the portal's top toolbar.
7

Create a resource — start the Azure Function setup

You are now on the Azure portal home (portal.azure.com/#home). Besides configuring Azure DevOps, this guide creates an Azure Function as the cloud resource that the DevOps pipeline will build and deploy to. Everything starts from the Create a resource shortcut, which opens the Azure Marketplace.

  1. If you don't have a subscription yet, the home screen offers options such as “Start with an Azure free trial” ($200 credit for 30 days plus 12 months of popular free services) or “Azure for Students”.
  2. Under Azure services, click Create a resource — the first tile with the + icon (highlighted in red below).
  3. The Create a resource page (Marketplace) opens; in the next steps you will search for Function App and configure it.

Step 7 — On the portal home, click "Create a resource" to begin creating the Azure Function.

💡 Tip: You can reach the same page from anywhere in the portal: click + Create a resource in the top-left toolbar, or press G+/ from the global search bar.
8

Choose “Function App” from the Marketplace

The Create a resource page is Azure's Marketplace, with categories on the left (Compute, Databases, DevOps, Web, …) and popular services and products in the center. The service we need — a Function App — is among the most popular, so it appears right at the top.

  1. On the Create a resource page, locate Function App in the Popular Azure services list (highlighted in red below) — or type “Function App” into the Search services and marketplace box.
  2. Click Create on the Function App tile (or the tile itself).
  3. The Create Function App wizard opens, starting with the Basics tab that you will fill in next.

Step 8 — Pick "Function App" (the lightning-bolt icon) from the Marketplace.

💡 Tip: Don't confuse Function App with Web App — both are compute services shown near each other in the list. A Function App hosts event-driven, serverless code; a Web App hosts a continuously running website or API.
9

Activate an Azure free trial (no subscription yet)

Every resource in Azure — including a Function App — must live inside a subscription. If your account doesn't have one yet, Azure intercepts the Create a resource flow and shows the “Welcome to Azure! Don't have a subscription?” page with sign-up options.

  1. On the “Welcome to Azure!” page, choose “Start with an Azure free trial” (highlighted in red below) and click Start. It includes $200 of free credit for 30 days plus 12 months of popular free services.
  2. Complete the free-trial sign-up form Azure presents: confirm your profile, verify your identity by phone, and add a credit card (used to validate your identity — you won't be charged unless you explicitly upgrade).
  3. Alternative: if you are a student, pick “Azure for Students” instead — it grants free credit without requiring a credit card.
  4. Once the trial is active, return to Create a resource and continue with the Function App selection from the previous step.

Step 9 — No subscription yet? Start the Azure free trial to unlock resource creation.

💡 Tip: The free trial is more than enough for this guide — a Function App on the Consumption plan falls within the free monthly grant (1 million executions). Set a spending alert in Cost Management anyway so you always know where you stand.
10

Open Users to invite collaborators as contributors

From the primary Azure account (the one that owns the subscription), the other members of the team will be invited to participate as contributors. The Users shortcut on the portal home takes you straight to user management in Microsoft Entra ID.

  1. On the Azure portal home, under Azure services, click the Users tile (highlighted in red below).
  2. The Users | All users page opens, listing every identity in your directory.
  3. From here you will invite the remaining team members (next step): add each user and then grant them the Contributor role so they can work on the subscription's resources — for example the Function App and its resource group.

Step 10 — Click "Users" to manage directory users and start inviting contributors.

💡 Tip: Contributor can create and manage everything under the granted scope, but cannot change who else has access — that requires Owner. Grant the role at the narrowest scope that makes sense (e.g., the project's resource group rather than the whole subscription).
11

Create or invite the new user

The Users | All users page (default directory) lists every identity in your tenant. Here you add the teammates who will collaborate on the project. The list shows both Member accounts and Guest accounts added by invitation — in the example below, a guest user added via invitation and the member Manuela Cortés Granados.

  1. On Users | All users, click + New user (highlighted in red below).
  2. Pick how to add the person:
    • Create new user — generates a corporate identity in your directory (id @<domain>.onmicrosoft.com with an auto-issued password).
    • Invite external user — sends an email invitation; ideal for personal accounts such as Gmail-registered Microsoft accounts. The person must redeem the invitation to gain access, and appears with User type: Guest.
  3. Fill in the identity basics (display name and email / user principal name) and click Review + create (or Invite for guests).
  4. Once the user exists in the directory, grant them the Contributor role (covered in the next step).

Step 11 — Click "+ New user" to add the next collaborator to the directory.

💡 Tip: Members authenticate with directory-managed credentials; guests keep using their own account (e.g., their Gmail-backed Microsoft account). For a study or demo project like this one, inviting external users as guests is usually the simplest path.
12

Choose “Invite external user”

The + New user button is actually a split button: clicking its arrow reveals the two ways of adding someone. Since the collaborators join with their own personal Microsoft accounts (Gmail-registered), the invitation route is the one to use.

  1. Open the + New user dropdown (highlighted in red below).
  2. Select “Invite external user” — “Invite an external user to collaborate with your organization” — rather than “Create new user”, which would mint an internal account (@<domain>.onmicrosoft.com) instead.
  3. The Invite external user form opens: enter the person's email address, a display name, and an optional welcome message.
  4. Review the assignment options shown on the form (you can add group memberships here), then click Review + invite to send the invitation.
  5. The guest receives an acceptance email; once they accept, they appear in the users list with User type: Guest.

Step 12 — Select "Invite external user" so collaborators can join with their own accounts.

💡 Tip: Invited guests keep signing in with their personal credentials — no new password to manage. If someone's invitation email never arrives, you can copy the direct redemption link shown after sending and share it with them yourself.
13

Fill in and send the invitation

The Invite external user wizard has four tabs — Basics, Properties, Assignments, and Review + invite. Only the Basics tab is required to get the guest into the directory.

  1. On the Basics tab, under Identity, enter the collaborator's email in Email — here veeduriabg@gmail.com. The Display name auto-fills from the address; adjust it to the person's real name if you prefer (both fields are highlighted in red below).
  2. Optionally type a short Message so the invitation doesn't feel like spam, and add a Cc recipient if someone else should get a copy. Leave Send invite message checked.
  3. Leave the Invite redirect URL at its default (myapplications.microsoft.com) — it's where the guest lands after accepting.
  4. Click Review + invite (highlighted at the bottom) to send the invitation right away. Alternatively, use Next: Properties to add job details first, or the Assignments tab to add the guest to groups or roles during the invite.
  5. The guest receives an email titled with your organization's invitation — they must accept it (redeem it) to become active.

Step 13 — Enter the guest's email, keep the defaults, and click "Review + invite".

💡 Tip: You don't have to assign the Contributor role during the invite — Assignments is optional. The next steps cover granting the role explicitly at the subscription scope, which is the more transparent way.
14

Review the summary and send the invite

The Review + invite tab condenses everything the guest will receive into one summary. Take a few seconds to verify it — once sent, the invitation email is on its way.

  1. Open the Review + invite tab (highlighted at the top).
  2. Check the summary: Email and Display name — veeduriabg@gmail.com in this example; Send invite message: Yes; the redirect URL; and under Properties, User type: Guest. The Assignments section (Groups, Roles) is empty because none were selected.
  3. Click Invite (highlighted at the bottom-left).
  4. A confirmation notification appears and the invitation email is sent. The guest must open it and accept — from that moment they show up in Users | All users as a Guest.

Step 14 — Verify the guest summary and click "Invite" to send the email invitation.

💡 Tip: If the guest says the email never arrived, open their profile under Users | All users and use the Resend invitation action — it regenerates the redemption link without creating a duplicate account.
15

Confirmation — “User invitation in progress”

As soon as you click Invite, the portal reports the result in the notification panel at the top-right of the toolbar.

  1. Look at the top-right corner of the portal — the notification (highlighted in red below) reads “User invitation in progress for user veeduriabg@gmail.com”.
  2. Within a few seconds it updates to “Successfully invited user” — the invitation email has been sent and the guest account now exists in the directory.
  3. The collaborator can now accept the invitation from their inbox; once accepted, they appear as an active guest in Users | All users.

Step 15 — The portal confirms the invitation is being processed for the guest user.

💡 Tip: Clicking the notification bell (the 1 badge next to it) opens the full notification history, useful to double-check that every teammate's invitation went through before moving on to role assignment.
16

Guest side — the invitation email arrives in Gmail

Now switching seats: everything so far was done by the subscription owner. From here, the steps are performed by the invited collaborator, starting in their own inbox.

  1. Sign in to Gmail with the invited account and look in the inbox for a message from “Microsoft Invitations” (highlighted in red below).
  2. The subject reads “Directorio predeterminado invited you to access applications within their organization” — the directory name your teammate entered on the invite.
  3. Note the security line in the preview: “Please only act on this email if you trust the organization represented below”. Verify you recognize the sender organization before doing anything else.
  4. Open the email and click Accept invitation — the redemption flow is covered in the next step.

Step 16 — In the guest's Gmail, open the Microsoft Invitations email.

💡 Tip: If the message isn't in the inbox, check Updates or spam — Microsoft invitation emails are occasionally auto-filtered on Gmail.
17

Open the email and accept the invitation

The invitation email contains everything needed to verify who is inviting you and where you will land after accepting — worth a quick check before clicking anything.

  1. Open the invitation email. Verify the sender: “Microsoft Invitations on behalf of Directorio predeterminado” (invites@microsoft.com) and the red warning banner about acting only on invitations you trust.
  2. Confirm the details in the body: Organization: Directorio predeterminado and Domain: manuelacortesgranadosgmail.onmicrosoft.com — your teammate's Azure directory.
  3. Click Accept invitation (highlighted in red below).
  4. The browser opens the redemption page at myapplications.microsoft.com, where you sign in with the invited Microsoft account and confirm access — covered next.

Step 17 — Verify organization and domain, then click "Accept invitation".

💡 Tip: The Domain line is the fastest authenticity check: it must match the tenant that invited you. If it references a domain you don't recognize, don't accept — report the email as phishing instead.
18

Guest accepts the requested permissions

After clicking Accept invitation and signing in with the invited Microsoft account, Microsoft shows the consent screen that formalizes the relationship between the guest and the organization's directory.

  1. Review the “Permissions requested by” screen: the organization is Directorio predeterminado (manuelacortesgranadosgmail.onmicrosoft.com).
  2. By accepting, you allow the organization to:
    • Receive your profile data.
    • Collect and log your activity.
    • Use your profile data and activity data.
  3. Click Accept (highlighted in red below) to grant the permissions and complete the redemption. Cancel aborts the process and the guest account stays inactive.
  4. You are redirected to myapplications.microsoft.com (My Apps), now appearing as a guest of the organization. From the owner's side, the user now shows as an active Guest in Users | All users.

Step 18 — Review the permissions and click "Accept" to finish redeeming the invitation.

💡 Tip: These are standard consent permissions for any guest invite (profile and activity data), not access to your files or mail. Guests can later review and revoke consent at myaccount.microsoft.com under Organizations.

Deployment complete — go to the resource

A couple of minutes after Create, the deployment's own Overview page confirms the result with a green check: “Your deployment is complete”. This page is reachable by clicking the completion notification, or under the resource group's Deployments blade.

  1. Read the deployment header: name Microsoft.Web-FunctionApp-Portal-d7487089-9723, subscription Azure subscription 1, resource group AzureResourceGroup1, plus the start time and the Correlation ID (useful when opening a support ticket).
  2. Expand Deployment details to see every resource the template provisioned — the Function App, its hosting plan, the storage account, and Application Insights.
  3. Click Go to resource (highlighted in red below) under Next steps — it opens the new Function App's overview page.
  4. The left menu here (Inputs, Outputs, Template) stays available: the Template view shows the exact ARM JSON that was deployed, ideal for reusing as Infrastructure as Code.

Step 32 — "Your deployment is complete" — click "Go to resource" to open the Function App.

💡 Tip: Bookmark the deployment's Template export (or the Download button in the toolbar): it's the fastest way to turn a portal-created resource into a repeatable Bicep/ARM deployment for future environments.

Azure DevOps sign-up — complete your profile details

  1. Review the profile panel on the left — Veeduria Ciudadana Informatica y Buen Gobierno, veeduriabg@gmail.com, account type Microsoft account, country Colombia — and use Edit profile if anything needs correcting.

35

Confirm the account and Continue

A compact confirmation dialog appears before the organization is actually provisioned — it binds the new organization to a specific Microsoft account and directory.

  1. Verify the identity shown at the top: veeduriabg@gmail.com. The new organization will be created under this account.

Name the organization and complete the CAPTCHA

Step 36 — Organization name, hosting region, CAPTCHA… then Continue.

💡 Tip: The organization name is the only part of the URL that's hard to change later, while the hosting region is fixed at creation. Decide both with the final team size and location in mind — renaming an org is possible but breaks every cloned repo URL and service hook.

Provisioning — “Taking you to your organization…”

  3. If the screen hangs for more than a minute, refresh the page — the organization is usually already created and the session simply needs to resume.

Step 37 — Brief provisioning spinner on the way into the new organization.

💡 Tip: From this point on, your organization's URL (dev.azure.com/veeduriaibg) is the single address your whole team needs — projects, repos, and pipelines all hang off it.
38

Create the first project

Inside the new organization, the first thing Azure DevOps asks for is a project — the container for your boards, repositories, pipelines, and test plans. This minimal form only needs a name and a visibility choice.

  1. Type the Project name — in this example ProyectoVeeduriaBG001 (highlighted in red below).
  2. Choose the Visibility: Private is selected here, so only the people you grant access to can view the project. Public is disabled for this organization — it can be turned on later via organization policies, with the caveat that some features (like TFVC) are not supported for public projects.
  3. The streamlined form applies DevOps defaults for everything else — Git version control and the Agile work item process — both changeable later in project settings.
  4. Click + Create project (highlighted in red, arrow annotation). After a few seconds the project's Summary page opens, with Boards, Repos, Pipelines, and Test Plans ready in the left menu.

Step 38 — Name the project, keep it Private, and click "+ Create project".

💡 Tip: Choose project names without spaces or special characters — the name becomes part of clone URLs, REST API paths, and pipeline identifiers. Renaming later is possible, but every old reference has to catch up.
39

Provisioning — “New project is being created…”

Right after clicking + Create project, the form grays out and a spinner appears. Behind the scenes, DevOps is scaffolding the project's default team, board, Git repository, and service connections.

  1. Wait a few seconds while the highlighted banner shows “New project is being created…” — the name field and visibility choice stay locked during this step.
  2. When provisioning finishes, the banner is replaced by the project's Summary page — the project home with its Wiki and dashboard shortcuts.
  3. If creation seems stuck, a page refresh usually resolves it; the project either exists or the form returns with an error explaining what to fix (most commonly, a duplicate project name).

Step 39 — The brief provisioning spinner right after "+ Create project".

💡 Tip: Provisioning also creates a default team named after the project (with its own backlog and dashboard) — you can add more teams later in Project settings, one team per work stream.
40

Project created — open Repos

  2. Click Repos in the left menu (highlighted in red with the arrow annotation below) — or the Repos shortcut button in the welcome panel.
  3. Repos opens the project's empty Git repository, offering to clone it, import existing code, or initialize it with a README — the next step of the guide.

Step 40 — The project is live; open Repos to start with source control.

💡 Tip: Every service is also reachable from the horizonal switcher at the very top of the page — useful once you work across several projects in the same organization.

  5. The directory is ready; next comes granting the Contributor role on the subscription.

💡 Tip: If a guest shows up but with a Pending acceptance state, they haven't redeemed the invitation yet — open their profile and use Resend invitation, or share the redemption link directly.

Open Azure subscription 1

Step 22 — Open "Azure subscription 1" (Active, you are Owner) to manage its access.

Open Access control (IAM) from the subscription Overview

Inside Azure subscription 1, the Overview blade shows the essentials (ID, directory, status, your role, plan) plus cost and usage charts. The menu on the left is where access management lives.

Open Access control (IAM) → Role assignments on the subscription

With the guest active in the directory, it's time to grant them permissions over the subscription's resources. Back on the owner's account, Azure RBAC (role-based access control) is managed from the subscription's Access control (IAM) blade.

  1. From the portal, go to Subscriptions and open Azure subscription 1.
  2. In the left menu, click Access control (IAM) (highlighted in red below).
  3. Select the Role assignments tab (highlighted, with the arrow annotation) — this lists everyone who currently has a role on the subscription.
  4. To grant the Contributor role, click Add role assignment in the “Grant access to this resource” card — or the + Add button at the top of the blade. The assignment wizard is covered in the next steps.

Step 24 — On the subscription, open Access control (IAM) and go to the Role assignments tab.

💡 Tip: The orange banner about classic administrator roles being retired (August 31, 2024) only matters for old Co-Administrator/Service Administrator setups — always use Azure RBAC roles like Contributor, as this guide does.

Start the assignment — Add → Add role assignment

On the Role assignments tab you can review who already has access — the list below shows Owner (2) and Contributor (2) entries at the This resource scope, with 5 of the 4,000 allowed assignments in use. To add a new one, the + Add button in the toolbar opens the correct entry point.

  1. On the Role assignments tab, open the + Add dropdown in the toolbar (highlighted in red below).
  2. Choose Add role assignment — the RBAC route.
  3. Avoid the other two options: Add co-administrator belongs to the retired classic administrator model, and Add custom role is for defining brand-new role definitions, not assigning existing ones.
  4. The Add role assignment wizard opens with its four tabs — Role, Members, Conditions, and Review + assign — configured in the following steps.

Step 25 — Toolbar "+ Add" → "Add role assignment" starts the wizard.

Select the hosting option — Flex Consumption

The Create Function App wizard starts by asking how the app will be hosted — this choice determines how it scales, what resources each instance gets, and how it is billed. The page lays the five options side by side in a comparison table.

  1. Review the comparison table: Scale to zero, Scale behavior, Virtual networking, Dedicated compute / cold start, and Max scale out (instances).
  2. Select Flex Consumption (highlighted in red below) — high scalability with compute choices, virtual networking support, pay-as-you-go billing, scale to zero, fast event-driven scaling, and up to 1,000 instances.
  3. The alternatives, for reference: Consumption (the classic pay-per-execution plan, up to 200 instances), Functions Premium (pre-warmed instances, no cold start), App Service (runs web and function apps on a dedicated plan), and Container Apps environment (containerized microservices with KEDA).
  4. Click Select (highlighted at the bottom-left) to confirm and move on to the Basics tab.

Step 28 — Pick "Flex Consumption" and click Select to continue.

💡 Tip: For a learning or low-traffic project, Flex Consumption and classic Consumption are effectively free at small volumes (monthly free grant). Flex is the newer generation and the portal's default — a safe choice for this guide.

  2. Check the Details block: subscription 0e9f2fce-…, resource group AzureResourceGroup1, name FunctionAppGrupoLoyal, runtime .NET 8 (LTS), isolated worker model, instance size 2048 MB.

Confirmation — “Initializing deployment” of the Function App

After the Function App wizard's final Review + create validation passes and Create is clicked, Azure submits an ARM template deployment behind the scenes — the portal reports it immediately in the notification panel.

  1. Look at the top-right notification (highlighted in red below): “Initializing deployment…” — Initializing template deployment to resource group ‘AzureResourceGroup1’.
  2. This means the Function App and its dependencies (storage account, Application Insights, hosting plan) are being rolled out as a single template deployment into AzureResourceGroup1.
  3. After a minute or two the notification changes to “Deployment is in progress” and finally “Your deployment is complete”, with a Go to resource shortcut.
  4. To follow the rollout in detail, open the resource group (AzureResourceGroup1) and check Deployments — or click the notification itself, which links to the deployment's progress page.

Step 31 — The template deployment to AzureResourceGroup1 has started.

💡 Tip: A Function App deployment typically completes in 2–4 minutes. Navigating away doesn't cancel it — but keeping the notification open makes it easy to jump straight to the finished resource via Go to resource.

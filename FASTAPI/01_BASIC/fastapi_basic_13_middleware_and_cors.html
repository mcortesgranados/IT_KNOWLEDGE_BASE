Middleware and CORS

Middleware wraps every request/response passing through the application. It is the place for cross-cutting concerns: CORS, logging, timing, compression, security headers, request IDs.

How Middleware Works

A middleware is a function that receives the request and a call_next delegate. Code before call_next runs on the way in; code after runs on the way out.

import time
from fastapi import FastAPI, Request

app = FastAPI()

@app.middleware("http")
async def add_process_time_header(request: Request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    elapsed = time.perf_counter() - start
    response.headers["X-Process-Time"] = f"{elapsed:.4f}"
    return response

CORS: The Most Common Middleware

Browsers block JavaScript on https://mysite.com from calling https://api.mysite.com unless the API answers with CORS headers.

from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://mysite.com", "http://localhost:3000"],
    allow_credentials=True,
    allow_methods=["*"],     # or ["GET", "POST"]
    allow_headers=["*"],     # or ["Authorization", "Content-Type"]
)
  • Never use allow_origins=["*"] with allow_credentials=True — the spec forbids that combination for credentialed requests, and it is insecure anyway.
  • Preflight: for non-simple requests the browser first sends OPTIONS; CORSMiddleware answers it automatically.
  • CORS is enforced by the browser; curl/Postman ignore it. "It works in Postman but not in the browser" is almost always CORS.

Built-in Middlewares Worth Knowing

import gzip
from fastapi.middleware.gzip import GZipMiddleware

app.add_middleware(GZipMiddleware, minimum_size=1000)  # compress big responses
  • GZipMiddleware: gzips responses larger than minimum_size bytes when the client accepts it.
  • TrustedHostMiddleware: rejects requests with unexpected Host headers (defense against host-header attacks).
  • HTTPSRedirectMiddleware: redirects all HTTP traffic to HTTPS.
  • ASGI ecosystem: sentry-sdk, uvicorn.workers proxies, and libraries like asgi-correlation-id plug in the same way.

Class-Based Middleware

from starlette.middleware.base import BaseHTTPMiddleware

class RequestIDMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        import uuid
        request.state.request_id = str(uuid.uuid4())
        response = await call_next(request)
        response.headers["X-Request-ID"] = request.state.request_id
        return response

app.add_middleware(RequestIDMiddleware)

Use classes (or pure ASGI middleware for maximum performance) when you need configuration passed to the constructor. request.state is a scratchpad shared with endpoints and dependencies during the request.

Quick Questions and Answers

Q: Middleware vs dependencies — when to use which?

A: Middleware sees every request and works at the raw ASGI level (no access to validated parameters or route info) — use it for CORS, compression, timing, tracing. Dependencies are per-route, typed, can raise HTTP errors and appear in docs — use them for auth, DB sessions, pagination.

Q: Does middleware execution order matter?

A: Yes. The last middleware added is the outermost — it runs first on the request and last on the response. Plan order accordingly (e.g. request-ID middleware should wrap everything else).

Q: My CORS setup works for GET but fails for POST with JSON. Why?

A: A POST with Content-Type: application/json is a non-simple request, so the browser sends a preflight OPTIONS. Either allow_headers does not include Content-Type/your custom header, or another route/handler is intercepting OPTIONS before the CORS middleware.

Conclusion

Middleware is your global request pipeline: time requests, inject correlation IDs, compress, enforce hosts — and configure CORSMiddleware with explicit origins to let browsers call your API safely.
